# Release safety contract

Release verification is local and deterministic. Preserve canonical profiles, document hashes, packet revisions, manual edits, exact approvals and independent application outcome/session state.

Run focused checks before full Python coverage, complete UI and isolated worker/draft integrations. Use disposable synthetic data and fake adapters; block external requests. Production verification is read-only and compares protected-state fingerprints.

Preparation, Gmail draft creation, sending, submission and scheduling are separate authorization boundaries. This source checkpoint grants none of those live actions. Unknown evidence remains unresolved. Failed or uncertain writes never replay blindly. Schedule configuration is not execution evidence.

Current implementation and actual validation: ../docs/privacy-refactor-verification.md. Historical live operational reports remain private and are not release instructions. Production visual/design acceptance remains pending.
