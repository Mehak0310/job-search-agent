# Command Center product redesign

Preserve R1 eligibility, history, worker ownership and manual submission controls and R2 canonical facts, strict priority and exact draft approval. This is a presentation integration, not a replacement backend. No new polling, external actions, schedules, accounts or model calls.

Six workspaces: Home (Overview, My Actions, Recent Activity); Find Jobs (Best Matches, Shortlisted, All Jobs, Needs Verification); Applications (Priority Queue, Preparing, Ready to Review, Applied, Follow-ups); Inbox & Drafts (Recruiter Inbox, Job Alerts, Draft Approvals, Draft History); Sources & Activity (Source Health, Run History, Schedules, Verification Backlog); My Profile (Career Facts, Documents, Saved Answers, Preferences). Settings remains outside primary navigation. Old hash routes remain compatible.

Use a fixed 232/72px sidebar, 64px header, 24px main padding and responsive single-column mobile layout. Job list/detail split is 42/58; details retain direct links, relevance, independent checks and exact UNKNOWN reasons. Contextual details use nonmodal drawers; bounded answers and exact approval remain dialogs.

Reuse existing APIs and deterministic canonical projections. Loading failures must remain local; cached data must be marked stale. No fabricated source counts, schedule installation, eligibility or ready form claims. All legacy mutations retain existing explicit user controls and backend gates. Preserve keyboard navigation and read-only live validation.

Acceptance: route/feature parity, shell/subview/keyboard/responsive checks, full existing regression, integrated R1/R2, six desktop/mobile screenshots and controlled localhost activation with history/document preservation.
