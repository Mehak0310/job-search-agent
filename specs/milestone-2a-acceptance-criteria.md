# Milestone 2A acceptance criteria (before code changes)

1. Preserve Milestone 1 API imports, manual status/history/audit integrity and tests. Apply an atomic versioned migration, back up existing database first, and retain user profile edits and statuses.
2. Greenhouse connector reads public HTTPS jobs?content=true, validates a full-board response and rejects unexpected truncation. Lever reads JSON pages via skip/limit until a short page; global/EU hosts are explicit. No application POST, credentials, redirect following or arbitrary API hosts.
3. Invalid source IDs, oversized/invalid external responses, missing fields, HTTP 404/403/429/5xx, timeout and exhausted budgets yield stable safe errors. Retry only bounded transient errors, honor Retry-After without early retries, and use conditional caching when supported.
4. Persistent source registry supports config loading/upsert, enabled toggles, health, successful/attempt timestamps, error, cooldown and checkpoint. Seed enabled boards only after live verification.
5. Background discovery returns a run ID immediately; polling exposes terminal result and persisted per-source/aggregate metrics. A transactional cross-process lease prevents overlapping HTTP/CLI/scheduled runs. Failure on one source permits other eligible sources to finish. Config controls timeout, retries, cooldown, concurrency (sequential limit 1), request count and wall-clock budget.
6. Stable provider IDs/content signatures skip normalization/evaluation of unchanged records, retain first/last-seen/change timestamps and cross-source provenance. Full-board comparisons are local incremental processing, not an invented provider incremental endpoint. Changed records update descriptions/matching while preserving manual statuses and history; ambiguous cross-source conflicts are rejected without silently merging.
7. Classification returns the eight role categories, priority, explainable score, seniority, required/preferred/unknown skill distinctions and India eligibility. Frontend leadership and transition-friendly AI roles can score highly. Backend-heavy roles use 3.5 years specialization rather than seven. Remote without explicit India eligibility requires review; foreign-only remote is not marked eligible. Existing file-import matching remains compatible.
8. Dashboard supports bounded background discovery/polling, source health/toggles, successful scans, run counts/errors, categories/priorities/sources, match sorting and last-seen. Imported and fictional fixtures remain distinct from live public listings. Links open the original listing; no status/submission side effect.
9. Windows scheduling script is idempotent, default daily 08:00 Asia/Kolkata, independent of VS Code/Codex, and requires an explicit registration switch plus user approval. Document local timezone conversion, disabled-by-default setup, missed-run and optional catch-up behavior. Do not register a persistent task in this session.
10. All existing and new mocked automated tests pass, including parsing, pagination/retries/caching, registry, migration rollback, isolation, incremental updates, matching, API/background concurrency and metrics. Target 100%, minimum 90% Python statement coverage over modified/new scope. No automated test depends on live APIs.
11. After tests pass, perform small bounded runs against verified Greenhouse and Lever boards and repeat. Report real listings, category counts, requests, runtime, unchanged records, failures and preserved statuses. If live access fails, mark the affected provider criterion blocked. Browser automation unavailable => report API/HTML fallback honestly.
12. README/specs contain config, manual CLI, scheduling, metrics, known limitations and Milestone 2B seams. No external accounts, real submissions, system changes or GitHub PR.
